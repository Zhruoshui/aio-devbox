# mgr-web UI 优化:统一应用内弹窗、精简文案、i18n 溢出与表格对齐修复、工作区按钮整理

Refs: GitHub issue #18 (https://github.com/Zhruoshui/aio-devbox/issues/18)

## Goal

统一 mgr-web 的交互与视觉体验:消灭浏览器原生弹窗、精简冗余说明文案、修复英文 i18n 溢出与用量表格对齐问题、整理工作区按钮布局。

## Requirements

### R1 移除浏览器原生弹窗,统一为应用内对话框

现状:`ModelsPage.tsx`(L449/L474/L494/L516)与 `PresetList.tsx`(L226)使用原生 `prompt()` / `confirm()`。

- 所有 `prompt()` / `confirm()` 替换为应用内模态对话框,样式与现有"删除沙箱"确认弹窗一致(复用其组件/样式体系)。
- 原生 prompt 的输入功能(新建 profile 命名、profile 重命名)需要对话框内有文本输入框,支持回车提交、Esc 取消。
- 禁止引入新的第三方依赖;若项目内已有可复用的 Dialog/Modal 组件则复用,没有则抽一个轻量组件供各处使用。
- 完成后全仓(mgr-web/src)不得再有 `prompt(` / `confirm(` / `alert(` 调用。

### R2 精简/删除冗余说明文案

现状:i18n 中存在大量描述性长文案,例如"每个沙箱是一组彼此隔离的容器(网关 / app / VNC / code-server)。状态每 4 秒轮询一次;创建、重建、删除走长任务流并可查看日志。"

- 盘点 i18n.ts 中所有长描述/hint/subtitle 文案(中英双语)。
- 仅保留有操作指导价值的短语;纯解释系统内部机制(轮询间隔、容器拓扑、长任务流)的文案直接删除对应 UI 元素或 i18n key。
- 删除 key 时需同步删除引用,不留死代码。

### R3 修复英文 i18n 溢出

现状:中文正常,英文长文案在按钮/卡片/单元格中溢出。

- 排查按钮、卡片、徽章、表格单元格等容器的溢出处理。
- 英文模式下按钮、标签、卡片内文本不得溢出其容器(允许合理换行/省略,不得撑破布局)。

### R4 修复用量表格对齐

现状:用量统计表"输入 / 输出 / 缓存命中率 / 成本"列的内容与表头严重不对齐。

- 修复 th/td 的 padding、列宽策略,保证表头与数据列垂直对齐。

### R5 工作区按钮整理

现状:工作区有"折叠沙箱树"与"收起侧面板"两个按钮,实现同一功能;"重置布局"与"管理沙箱"按钮摆放位置不佳。

- 移除"收起侧面板"按钮,只保留"折叠沙箱树"。
- "重置布局"与"管理沙箱"改为水平排列。

## Constraints

- 仅改动 mgr-web/ 前端代码;不动后端 mgr/、gateway/ 等。
- 不引入新第三方依赖。
- 中英双语 i18n 同步修改(删除文案时两个语言都要处理)。

## Acceptance Criteria

- [ ] mgr-web/src 内无 `prompt(` / `confirm(` / `alert(` 原生调用;新建 profile、重命名、导入确认、删除确认均走应用内对话框
- [ ] 新对话框样式与"删除沙箱"弹窗一致
- [ ] 冗余长文案已简化或删除,无死 i18n key
- [ ] 英文模式下无文本溢出文本框/卡片
- [ ] 用量表格 th/td 对齐
- [ ] 工作区仅保留"折叠沙箱树";"重置布局"/"管理沙箱"水平排列
- [ ] `npm run build`(tsc --noEmit + vite build)通过
